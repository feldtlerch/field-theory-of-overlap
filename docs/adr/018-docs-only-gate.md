# ADR 018: Input equivalence for the docs-only gate · `rec:adr:018-docs-only-gate`

**Decision (Statement)** · `dec:docs-gate:equivalence`

A clean candidate commit may inherit the document verdict of a reviewed, green ancestor BASE when the docs-only gate proves that paper inputs and every generated byte are unchanged and the fast batteries pass; Markdown records, which statement-document preparation reads only for label admission, may change, and that admission runs in the engine-free tests and label checks. Run `python3 -I -B BASE_CHECKOUT/tools/docs_gate.py BASE --repository CANDIDATE_CHECKOUT` with separate clean checkouts: the judging code must come from BASE, outside the candidate, and the candidate must be HEAD with no staged, unstaged, untracked or ignored files. The gate checks these conditions and prints both commit identities; the caller supplies the trusted base checkout and its reviewed, green verdict. The caller also makes CANDIDATE_CHECKOUT, by fetching the candidate commit into a fresh clone of the base, because the gate reads the candidate's objects, refs and configuration; an author's repository is never judged in place. A PASS covers only the named candidate; every other retained commit between BASE and it needs its own verdict (`dec:process:signed-bites`). It neither establishes that an arbitrary base is green nor stores a cached verdict. The pinned toolchain and locked dependencies must be available offline, and `CARGO_TARGET_DIR` must name an absolute directory outside both checkouts.

The base paper receipt and closed source list identify protected inputs before record permissions are considered. Every crate, document source, unit, registry entry and generated artifact is protected, as are the native lock and preparation script in their entirety. Root Markdown records, LICENSE-CODE and LICENSE-DOCS, Markdown under docs/, licence text files under licenses/ and tooling READMEs are eligible only outside those inputs; unknown paths are refused. These records feed label validation, so label checks remain mandatory. Changes to gate code or any test are not docs-only changes. A pass proves unchanged bytes and modes for every generated file, including the receipt, prints their SHA-256 hashes and writes nothing.

**Reasons (Why)** · `arg:docs-gate:reasons`

Paper-input and generated-output identity, with Markdown label admission, preserve a base's document verdict without a fresh rendering. The fast batteries still run formatting, denied-warning Clippy, label fixtures and checking, gate tests and all support-independent workspace tests with `--no-fail-fast` and `--skip support_required`, offline in a private network namespace with support environment variables removed. Neither a typesetting command nor a mathematics-runner command is invoked; tests still exercise the audit library. A thin entry point owns no classification logic (`dec:workspace:norms`). Isolated Python invocation loads the base's helper rather than candidate modules before classification.

**Declined (Alternatives)** · `arg:docs-gate:declined`

ADR 006 declines generating without committing, hashes as staleness markers and “a separate verifier tool (drift by construction)” (`arg:generation:declined`). Generated artifacts remain committed; hashes report identity alongside exact byte comparison, never freshness, and any artifact difference refuses this gate and requires the existing readable-diff byte gate. This gate does not compute expected generated bytes or duplicate a generator. Its proof is limited to unchanged paper inputs and generated outputs, with Markdown label admission, against an already gated base. The record permissions are a second statement of what no generator or typesetting work area reads for emitted content; a change that makes one read a record location for emitted content must withdraw that location from the permissions in the same change. Directory permissions alone would miss declared inputs; semantic lock or preparation exceptions require extra equivalence arguments and are not admitted. Cached verdicts and dependency-tracked builds remain separate decisions.

**Consequences (Accepted)** · `arg:docs-gate:consequences`

This record partially supersedes ADR 006's Decision clause “the gate regenerates and compares, a stale artifact fails with a readable diff, and a hand edit to a generated file is a build failure” (`dec:generation:byte-gated`): only for the input-equivalent, output-identical class above, inheritance from a reviewed, green base replaces regeneration. The stale-artifact and hand-edit obligations remain; this gate refuses changed artifacts and does not establish freshness independently of that base. ADR 006's deterministic committed artifacts and shared generation/check code path remain unchanged. Every refusal requires the full gate; this gate never substitutes for it on a refused change. This process decision adds no numbered validation rule.

Exit zero means PASS for the named candidate after all batteries and a final unchanged-tree proof; exit two means refusal. `--classify-only` prints eligibility and exits three for an eligible candidate, without running batteries or granting a gate verdict.

Every battery and the whole gate print JSON measurements: wall time, process-plus-waited-descendant user and system CPU, and start, end and delta cgroup v2 CPU, pressure and memory samples, with scope and unavailable files named. Cgroup samples include other work sharing that scope; pressure averages and memory gauges are samples, their differences are not attributed consumption, and memory.peak is the scope's lifetime peak. Measurements are observations, never gated document content.
