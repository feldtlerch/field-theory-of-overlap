# ADR 033: Inline styles in unit prose · `rec:adr:033-unit-inline-styles`

**Decision (Statement)** · `dec:units:inline-styles`

Unit prose names a closed set of four presentation meanings: `@emphasis{...}` for emphasis, `@strong{...}` for strong weight, `@smallcaps{...}` for small capitals, and `@regular{...}` for a regular-face reset. These follow the existing `@name{...}` insertion pattern and are scanned with source spans by the single insertion scanner in `units/content.rs`; each run retains the identity and spelling of any existing backtick citation or double-backtick mention inside it. No second citation or code spelling is introduced. The inherited direct forms map as follows:

| Inherited form | Unit meaning | TeX rendering | Markdown rendering | HTML rendering |
| --- | --- | --- | --- | --- |
| `\emph{...}` or scoped `\itshape` | `@emphasis{...}` | `\emph{...}` | `*...*` | `<em>...</em>` |
| `\textbf{...}` | `@strong{...}` | `\textbf{...}` | `**...**` | `<strong>...</strong>` |
| Scoped `\scshape` | `@smallcaps{...}` | `{\scshape ...}` | Refused; the tested attribute was removed | `<span style="font-variant:small-caps">...</span>` |
| `\textbf{\normalfont ...}` | `@regular{...}` | `{\normalfont ...}` | Refused; the tested attribute was removed | `<span style="font-weight:normal;font-style:normal">...</span>` |

The inline-style observation register (`reg:documents:markdown-inline-styles-observations`) records faithful `*...*` emphasis and `**...**` strong weight in the observed paragraph, table and list contexts. It also records that the forge removes inline `style` attributes: small capitals in the two title blocks and the regular-face reset in a table header cannot retain their requested face there. Markdown refuses those two kinds and any unobserved emphasis or strong context at their source sites. The observed nested candidates do not admit authored nesting, and observed styled mathematics does not override ADR 022. HTML rendering requires the face and licence evidence for every embedded font. The inherited `\texttt{...}` and `\verb|...|` forms have the unit dialect's existing double-backtick mention meaning, using that path's spelling, escaping and recovery; code is not an inline style. The existing mention scanner refuses a backslash, so the inherited `\verb|\RegisterVariance|` occurrence must refuse conversion until that same mention path can admit and recover its literal content. A single-backtick span remains a citation with its checked label, and a double-backtick span remains a mention without a harvested citation (`rec:adr:012-the-weld`).

Style runs are balanced and nonempty. The scanner refuses nested styles, whitespace just inside either boundary, adjacent runs of the same style without separating content, and a run containing its own emitted closing delimiter. It also refuses styled mathematics under ADR 022 (`dec:documents:markdown-mathematics`). Display regions admit no inline style under M058's admitted-body boundary. Emission and recovery compare the ordered run boundaries, meaning, text, tag identities, citation identities and mention contents; moving or deleting a boundary while retaining the words is unequal.

**Reasons (Why)** · `arg:units:inline-styles-reasons`

Meaning names preserve ADR 021's single reader-character authoring language (`dec:units:reader-character-typography`): TeX command names are source forms to convert, not unit kinds. The twelve body files contain 561 direct style and code calls, counted in `reg:documents:markdown-inline-styles-observations`; 310 `\emph`, 234 `\textbf`, 13 `\itshape`, two `\scshape`, one `\texttt`, and one `\verb`. The three `\textbf{\normalfont ...}` calls on one table-header line cancel the outer bold and therefore require the regular-face meaning rather than strong weight. No style argument in those files contains another style call. One scanner retains the existing insertion and span diagnostics, and boundary comparison preserves presentation distinctions that a word-only comparison would miss. Emitting those two kinds as unstyled Markdown words would produce the same bytes whether either boundary existed, moved or disappeared, defeating boundary recovery; invisible comments at both ends could carry a boundary without changing the visible words, but their survival in a heading and a table header cell has not been observed. They therefore do not admit small capitals or regular weight to Markdown; adopting them would require recorded observation and a reviewed boundary spelling.

**Declined (Alternatives)** · `arg:units:inline-styles-declined`

TeX input names as unit kinds would split equivalent emphasis into `emph` and `itshape` while making the authoring language depend on one renderer. A separate leaf grammar would duplicate `units/content.rs` and disagree on spans, escaping and admitted insertions. A second code spelling would be indistinguishable from existing mentions after emission and recovery. Nesting has no source occurrence and introduces ambiguous boundaries and unchecked depth; it is refused with a located diagnostic.

**Consequences (Accepted)** · `arg:units:inline-styles-consequences`

This decides the style authoring syntax left open by ADR 021 (`rec:adr:021-unit-prose-typography`) without changing its character mapping, ADR 005's one-text rule or ADR 017's two Markdown roles. The scanner, TeX and HTML writers, Markdown writer, and recovery must share one located run model and refuse a missing embedded face or an unobserved or unfaithful Markdown form. The `\gradeword`, `\gloss` and `\virtue` macros are outside this direct-call decision and retain their source-defined presentations (`documents/paper/macros_overlap.tex` and `documents/paper/main_explainer.tex.in`); tag and reference identity and appearance remain governed by ADR 003, ADR 017 and ADR 037 (`rec:adr:003-tags-bound-to-labels`, `rec:adr:017-screen-rendering-contracts`, `rec:adr:037-native-paper-tagged-paragraphs`). Table, list, heading and display structure remain outside this style decision, and no font delivery is asserted by this record.
