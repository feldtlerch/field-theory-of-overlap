# ADR 022: Mathematics transport in forge Markdown · `rec:adr:022-markdown-mathematics`

**Decision (Statement)** · `dec:documents:markdown-mathematics`

Inline mathematics uses dollar-backtick delimiters in these observed Markdown contexts: ordinary unstyled running prose, including two formulas in a paragraph, line boundaries and punctuation followed by a space; GFM table body cells; simple top-level unordered list items; ordinary level-four headings; and beside label comments with a space before the opening delimiter. Display mathematics uses double dollars on separate lines in a top-level block with blank lines around it. Mathematics in every HTML block and every other unobserved context is refused, including blockquotes, styled spans, link text, nested structures and an opening delimiter directly after a tag or citation comment. The heading observation covers only a single-subscript body. Both Markdown roles use the same bodies and envelopes, with comments outside mathematics; erasing the annotated role's recognized comments yields the reader role exactly. Bodies remain fully expanded strict KaTeX from the one checked notation AST, without document macros, under ADR 004 (`rec:adr:004-notation-ast`) and ADR 017 (`rec:adr:017-screen-rendering-contracts`).

On 2026-11-18, 51 numbered cases were observed in the signed-out forge view at public commit 3e95972, experiments/markdown-view/math/, with Chromium 156 on Linux. Protected inline mathematics typeset in the named contexts (M02, M09B–M21B, M24B); ordinary dollars lost characters in tested Markdown cases (M01, M09A, M10A, M12A, M16A, M42A, M47A). Double-dollar displays typeset alignment, cases and matrices (M31–M33); M31 records exact row endings, while the fenced M25 input acquired a backslash. M22A's plain-dollar centred HTML example worked, but is not admitted here; M22B introduced quotes and M23 failed inside emphasis. Tags had unusable layout (M28, M34), equation environments supplied no number (M29, M35), and the named-operator example was rejected (M44). These observations identify neither the engine nor general compatibility. Received bytes were recorded only for the cases identified in the evidence register; other transport conclusions are inferred from rendering. No mathematical web font loaded and no installed-font inventory was taken. Underbrace, Greek, alphabet styles, box and prime appearance remain unresolved across browsers and fonts (M02, M39, M43, M46, M47). The dated cases, exact candidate pages and distinctions between measurement, inference and admission are retained in registry/markdown-mathematics.md and its linked dated files (`reg:documents:markdown-mathematics-observations`).

**Reasons (Why)** · `arg:documents:markdown-mathematics-reasons`

One inline envelope avoids context-dependent body rewriting and redundant writer branches. Explicitly bounded contexts protect checked notation from a preceding Markdown parse without claiming unseen combinations work. A closed notation contract and an appendable observation record supply different evidence: grammar acceptance does not establish forge rendering. Shared bodies and comment erasure preserve one authority for both roles. Separating transport from browser/font appearance prevents missing glyphs or layout support from silently changing mathematical meaning.

**Declined (Alternatives)** · `arg:documents:markdown-mathematics-declined`

Ordinary dollars corrupt observed Markdown bodies. A separate plain-HTML envelope has no required consumer and its one successful example does not establish other HTML contexts. Escaping individual underscores, adding groups or using fenced displays does not provide the observed transport contract. Arbitrary TeX, document macros, relaxed strictness and separately authored screen formulas weaken the shared notation authority. Automatic numbering and tags do not supply the plan's numbers in the observed view. Dropping boxes, braces or alphabet distinctions is not a repair for unresolved appearance.

**Consequences (Accepted)** · `arg:documents:markdown-mathematics-consequences`

This amends ADR 017's Decision reservation “decides neither the rest of that dialect nor those mathematics spellings” (`rec:adr:017-screen-rendering-contracts`) only for the mathematics envelopes, contexts and boundaries specified here. Its requirement “what that view accepts must be established by a test against that forge before the Markdown dialect and the mathematics spellings it uses are fixed” and its Consequences requirement “The forge test must precede fixing the Markdown dialect and mathematics spellings” are fulfilled for this bounded decision, not reversed; other dialect and HTML-delivery questions remain open. ADR 004's primitive admission, pinned spellings and strict checking remain. Inline bodies must not contain delimiter, table, HTML, emphasis or citation-boundary characters (backtick, dollar, pipe, less-than sign, ampersand, asterisk, colon or line break); any proposed primitive that introduces one requires an explicit reviewed boundary and observation before admission, not contextual escaping. Document emission refuses unsupported contexts and bodies at their source sites before sizing/rendering, and recovery refuses bare-dollar mathematics. New operations require strict admission and recorded observation; new contexts beyond this decision require an explicit admission decision. The appendable evidence record retains later observations without rewriting this dated decision. It can record a failure without weakening the admitted set silently. Shared plan numbering, public destinations, byte gates and independent screen acceptance remain ADR 017 obligations. This record fixes no unobserved number layout, table combination, operator replacement, font fallback or HTML mathematics delivery, and does not declare an unimplemented consumer complete.
