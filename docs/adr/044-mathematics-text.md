# ADR 044: Text and references inside mathematics · `rec:adr:044-mathematics-text`

**Decision (Statement)** · `dec:notation:mathematics-text`

Mathematical phrases are decoded text in a bounded expression node, rather than new symbols for each sentence. The literal node retains its one-letter-or-digits grammar. A text node contains ordered plain-text runs and, when a consuming document has checked its references, tag-reference runs; the first admitted form has only plain runs. It admits ASCII letters, spaces, comma and hyphen for the explainer flow, within explicit run, node and expression bounds. Adjacent spaces, commas and hyphens refuse because their decoded bytes acquire different rendering meanings. A text run does not accept nested mathematics, styles, TeX commands or markup. Catalogue bodies refuse text until a catalogue consumer exists. The owning unit and document resolve a future tag run through checked addressing; its occurrence and destination cannot be inferred from its printed letters.

Mathematical displays derive their target bodies from one shared expression selected by the owning unit. Display identity, ordered occurrences, destination and any number belong to the document plan, outside the expression. Only closed operations with actual consumers enter notation. Display spelling has its own checked grouping and spacing profile; existing inline spellings remain unchanged. Underbrace has a base and annotation, and the large slash in the coda is a fixed separator between three tenses, never division. The coda's box emphasizes the three-way formula; it does not change its assertion. PDF and HTML retain that box. Forge Markdown may carry the same words and operations without a box only with an explicit presentation limit, because that rendering has no faithful observed box. Phrases in any formula are informal words without graph identities; tagged mathematical objects retain their checked identities.

Native TeX renders decoded words within generated text boundaries and retains inherited source declarations and their checking interfaces. Strict expanded screen source contains no paper macro or trusted link command. HTML mathematical handles are plain lowercase, as in screen prose, and retain checked links in place. Forge mathematical handles are plain and unlinked in place, with checked targets retained in annotated Markdown outside the mathematical envelope, as governed by ADR 037 (`rec:adr:037-native-paper-tagged-paragraphs`); no forge legend is added. A number is ordinary Markdown adjacent to the formula, never a `\tag` command. Formula links do not change the presentation of prose handles. Mathematical rendering and recovery compare the expression's structure, text boundaries, ordered occurrences, destinations and any number; a source annotation alone cannot establish equality. A mathematical block outside an admitted HTML profile remains a plan-recorded gap under ADR 046 (`rec:adr:046-registered-html-block-gaps`) and M055/M065. The first display profile requires its own observation before emission.

**Reasons (Why)** · `arg:notation:mathematics-text-reasons`

The explainer flow's phrases explain terms rather than naming theory objects. One checked text boundary allows the same decoded words to be escaped for each renderer without widening mathematical literals. Document assembly already owns identity resolution; moving it into the notation catalogue would give that catalogue a second paper-reference authority. A distinct display spelling preserves the printed operators, thick spaces and underbrace attachments without changing the existing inline coefficient sources. Known forge observations show missing underbrace and Greek glyphs and an undrawn box; those appearance limits do not justify a different expression or a claim of faithful typography (`reg:documents:markdown-mathematics-observations`). The HTML probes establish useful component behaviour but do not alone admit the composed display (`rec:adr:042-html-mathematics`).

**Declined (Alternatives)** · `arg:notation:mathematics-text-declined`

A primitive for each phrase makes the primitive catalogue a prose inventory. Raw TeX text, authored HTML, arbitrary CSS, trusted links and general delimiters admit renderer instructions outside the checked expression language. Separate target-authored bodies can disagree about the equation. Flattening an underbrace, silently dropping a box, inventing a source label or guessing a number would change what recovery can attest. A partial-formula insertion route would add a second conversion mechanism to avoid admitting the complete explainer flow.

**Consequences (Accepted)** · `arg:notation:mathematics-text-consequences`

The explainer's unnumbered six-line flow is the first complete consumer. Its text grammar and closed operators enter before its document position and output. Alignrate, willnet and willdecay enter the compared support and native sweep ahead of their first converted scope. Each has one compared declaration site and no registered-variance site. The coda's tagged annotations, box, separators and number require their own checked consumer and observation. Text-only expressions can be checked without document references; a tag-bearing expression cannot be rendered until its document context has bound every tag. Authored underbrace text equal to the derived pending mark refuses, preserving the status mark's distinction. The expression's source ranges, rendered text and plan occurrences remain independent comparisons. Syntax admission makes no claim about quantity typing or mathematical truth. A source and PDF comparison must preserve the equation's ordered terms and grouping; complete-document word comparison alone cannot attest mathematical structure.
