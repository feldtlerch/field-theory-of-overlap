# ADR 040: Explicit transitional destinations in a placeholder index · `rec:adr:040-placeholder-index`

**Decision (Statement)** · `dec:documents:placeholder-index`

A converted screen reference to known content not yet converted resolves to an explicitly identified entry in a placeholder index at the end of the document that owns the target. The entry names the target with its public address and states that its content is not yet available in this rendering. It is a destination for the reference, not the missing content and not a link to a location in the PDF. Ordinary missing-content notices at their positions in the reading remain unlinked. Conversion of the target moves its existing public destination from the index to its body, with one live destination and no change of reference identity. Every entry and notice is derived from the document plan's availability and destination inventory. A rendering with either still fails the complete-document release gate.

**Reasons (Why)** · `arg:documents:placeholder-index-reasons`

An explicit unavailable destination tells readers where a reference leads without pretending that its content has been converted. A single end index makes the extent of unavailable targets inspectable and allows references to retain their public identity during conversion. The shared inventory prevents a missing target from disappearing between renderings. Keeping PDF destinations in the PDF and screen destinations in the screen document that owns the target avoids dependence on a particular PDF viewer.

**Declined (Alternatives)** · `arg:documents:placeholder-index-declined`

A link that looks like a converted passage but shows no unavailable-content notice misrepresents what can be read. Dropping a reference until its target is converted loses its identity; linking to the published PDF instead changes the reading medium. Requiring all referenced content to be converted first couples otherwise separate passages. Independently authored index entries would duplicate availability and destination authority.

**Consequences (Accepted)** · `arg:documents:placeholder-index-consequences`

ADR 017's effective missing-content clause (`rec:adr:017-screen-rendering-contracts`), as replaced by ADR 030:19 (`rec:adr:030-native-renderings-complete-graph-native-model`), “Where rendered content is not yet native, a screen rendering must show a placeholder message without a link; such a rendering cannot satisfy ADR 016's complete-document release gate for native passages and table bodies (`rec:adr:016-admission-and-native-documents`).” becomes: “Where rendered content is not yet native, a screen rendering must show an unlinked placeholder message at its position in the reading. A converted reference to a known unconverted target links to that target's explicit unavailable-content entry in the end placeholder index of the document that owns the target. A rendering that contains either cannot satisfy ADR 016's complete-document release gate for native passages and table bodies (`rec:adr:016-admission-and-native-documents`).”

ADR 017:15's sentence “These placeholders do not replace the required links of converted quotations and references.” becomes: “Converted quotations and references retain their required links; for a reference, an explicit placeholder-index destination may stand for a known target whose body is not yet converted, without claiming that its content is available.”

ADR 017:28's reason “Unlinked placeholders expose missing conversion without offering a destination that does not yet exist or implying document completeness.” becomes: “Unlinked notices expose missing conversion at its reading position; explicit end-index destinations preserve references to known unconverted targets without implying content availability or document completeness.”

ADR 017:35's sentence “Linking an unconverted placeholder misrepresents what can be read.” becomes: “Linking to missing content without explicitly identifying its unavailability misrepresents what can be read; an explicit end-index entry names that absence rather than presenting it as content.”

These qualifications concern transitional screen destinations only. They do not change PDF destinations, public binding lifetime, quotation ownership, required shared text, numbering, reader-label exclusion, review requirements or ADR 030's release boundary. ADR 025's clause remains unchanged: “Quotations identify another reading's owning occurrence and add no ownership or mint; writers that emit them share its language text and destination and give an explicit unlinked notice for an unavailable owner.” (`rec:adr:025-identified-reading-trees`). The index exception applies to references, not to that unavailable-owner condition; it supplies no text and cannot manufacture a quotation. PDFs carry no placeholder index: explainer.pdf links resolve in paper.pdf, and no pilot name is reader-visible in any rendering at release. Index entries require unique public destinations and are removed as their targets become available. No registered machine rule changes state through this record; its first generated index consumer adds destination and availability checks, including a release-mode refusal for any index entry or missing-content notice.

This record adds `@see{label}` as one located inline insertion for a declared paper appendix heading, following the existing `@name{...}` insertion pattern named by ADR 033 (`rec:adr:033-unit-inline-styles`). The scanner retains its label and source site. The shared plan derives the screen locator from source heading order and resolves the owning document and public destination; the Markdown writer recovers the reference against that plan. The PDF fragment is checked by regenerated bytes, preparation's label check and the identity ledger. The screen locator is the paper's own appendix number: every pair build compares the plan's derived number with the typesetter's counter and PDF destination, so the renderings agree as ADR 017:11 requires (`rec:adr:017-screen-rendering-contracts`); as for every inherited PDF number, the PDF's number remains the typesetter's until conversion. This insertion adds no tag mint and changes no style form.

ADR 046 (`rec:adr:046-registered-html-block-gaps`) says “The product-only `paper check-registered-html-gaps --built` command compares the ordered register with the plan's complete gap inventory, so an added, removed or changed gap refuses; it then requires all release parts other than HTML block gaps to pass and requires the ordinary release refusal at HTML block gaps to name the registered inventory.” This record replaces that sentence with: “The product-only `paper check-registered-html-gaps --built` command compares both ordered registers with their complete plan inventories, so an added, removed or changed gap refuses; it then requires all release parts other than HTML block gaps and screen destinations to pass. The ordinary release regression test `support_required_release_refuses_each_registered_gap_part` requires a refusal at each nonempty part that names its inventory.” The command keeps ADR 046's name while also comparing `registry/screen-destination-gaps.json` with unavailable index entries and positional content gaps. Both registers are compared in development and ordinary release; registration permits development notices but does not satisfy release. ADR 046 also says “The development product test is green only when the register exactly matches the plan and every other release part passes.” This record replaces that sentence with: “The development product test is green only when both registers exactly match their complete plan inventories and every release part other than HTML block gaps and screen destinations passes.” Ordinary release refuses either nonempty inventory by its part name, and a release requires both inventories to be empty. ADR 009's clause and ADR 020's sentence quoted in ADR 046, and ADR 030's sentence “No placeholder message for missing content satisfies this gate.” remain unchanged. ADR 017's sentences quoted in ADR 046 are replaced above; the replacement of the missing-content clause retains refusal at ADR 016's complete-document release gate. This record amends M055 with its see-reference sentences, checked see references in its fragment sentence and paper pair builds in its scope; it amends M065 with unavailable screen destinations, content gaps and HTML block gaps in its release statement and the screen-destination and content-gap part in its scope. M065's earlier scope sentence “The paper check --release consumer conjoins existing identity, acceptance, HTML block gap and byte checks and names the failing part in one release refusal.” becomes: “The paper check --release consumer conjoins existing identity, screen-destination and content-gap, HTML block gap, acceptance and byte checks and names the failing part in one release refusal.”
