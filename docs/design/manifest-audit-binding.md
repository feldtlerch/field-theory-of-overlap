# Manifest audit binding and checked coverage · `proposal:manifest:audited-binding-bite`

## Boundary and evidence · `sec:manifest3:boundary`

M3 joins the manifest's closed graph to the engine audit through a closed producer registry, reviewed budgets, premise scheduling, typed verdict consumption and a release assessment. It enters as two separately reviewed bites, M3a and M3b, each with its checking consumer. The manifest remains engine-independent Rust authority; the audit depends on both the manifest and the pinned engine. A structurally valid graph is not thereby audited, and a valid audit report is not thereby a passing release (`dec:audit:engine-of-record`, `dec:graph:status-and-coverage`).

The kernel reference is main at `b8c7c9f9cc5a7b341f85e521ea69e66860c2f0a8`, including `crates/ftoo_manifest` and the standalone `crates/ftoo_audit` trial. The settled predecessor is `manifest-kernel.md` (`proposal:manifest:kernel-bite`, `reg:manifest:successors`). Its successor register permits M3 to consume validated Rust data before M1b. M1a derives Deferred for every claim, refuses every nonempty slice and completeness assertion, and registers M020 as deferred. The trial supplies exact linear-system witnesses, a bad-certificate negative and an independent series-division oracle, but neither manifest binding nor a complete account of the engine's capabilities.

The full engine pin is `a5cb0ab0d1763e8ed620f7c765fdd8d3b26b65ad`. At this pin `series.source`, `series.reciprocal` and `series.residual` are registered public capabilities. ADR 007's account of capabilities awaited at the outset is historical motivation, not a capability table for every later pin. The trial's linear route does not establish that the engine lacks formal series. M3 uses checked object composition and evaluated residual construction to move coefficient-equation derivation onto the engine, while keeping the analytic identification of the Langevin function explicit as the theorem's scope (`arg:audit:consequences`, `arg:audit:declined`).

There are exactly four theory nodes, two value-claim producers and six edges. No vector claim, unrelated theory structure, exclusive-route content or new mathematical identity is invented to exercise machinery. The producers share construction helpers but retain separate functions, bindings, budgets and fresh stores. Repeating the small checked jet preserves the landed identities and the fresh-store contract (`arg:audit:reasons`).

## Reviewed split and admission schedule · `reg:manifest3:bites`

M3a admits binding with actual producer execution; M3b admits semantic report consumption and release assessment. This split is part of the design, not a contingency left to implementation. M3a proves that the declared producers match a closed registry and execute the checked ODE route at the pin. M3b consumes those executions to establish audited evidence, total claim reporting, provenance and release eligibility. Neither half lands a layer without its checking consumer (`dec:process:signed-bites`, `arg:process:consequences`).

|Bite|Admission|Consumer and evidence|Explicit exclusion|
|---|---|---|---|
|M3a — bound execution|ClaimAudit sum; descriptors, capabilities and budgets; both-direction registry; exact dependencies; two composition/residual producers; minimal execution report.|The audit's fixed registry runs selected producers at the real pin and returns checked receipts; engine tests replay independently specified Compose, evaluated residual and Member judgments.|No Certified status, full four-verdict report, deferral propagation, provenance snapshot, release assessment or Complete acceptance.|
|M3b — audited evidence and release|Verdict semantics; private AuditedStatus and AuditReport; semantic snapshot; every-claim outcomes; deferral propagation; report and release predicates.|The report consumer checks provenance and outcomes, privately derives audited statuses and assesses release; engine and pure-consumption tests distinguish proof from synthetic fixtures.|No projection/report codec, CLI, exclusive-route implementation or unrelated theory structures.|

M3a returns `ProducerRun`, borrowing the immutable ValidatedManifest for its lifetime. It contains selected IDs in deterministic dispatch order and one immutable receipt per selected claim: claim and producer IDs, producer revision, BudgetId and resolved limits, full pin, target coefficient index, fixed jet and ODE summary, truncation parameters, and accepted portable Compose/residual/Member evidence. The subject summary identifies the identity composition Compose(J, h) = J, records h and both input orders, and pins the assumption-free ambient Product context. It records engine acceptance, not a public Certified evidence value. Receipts have private fields and no public constructor. There are no rows for unselected claims, assertion of release success, detached-input cache or public conversion to AuditReport. Measurements are separate.

ProducerRun is returned only if every selected producer completes. An unavailable adapter capability, missing accepted premise, exhaustion or rejected construction returns a typed RunError carrying claim, stage and actual cause; the first failed execution stops the run. This preserves information without implementing M3b's verdict propagation early. M3b replaces that public entry with `audit` returning AuditReport, using receipt-producing functions privately; it does not import caller-supplied ProducerRun objects as proof.

M3a retains base Status. Its seed changes both claims to Bound, selects both and asserts audit closure, while referent/relation closure remain false and the gate ExplicitPartial. M3a's M015 admits only this partial declaration family: false theory closures, ExplicitPartial, and audit closure true only if every claim is Bound and the registry matches. Nonempty execution therefore does not promise a release predicate that has not landed. M3b admits reviewed true theory-closure assertions and complete assessment. Remove the bare `Coverage::is_explicit_partial()` in M3a; no declaration-only replacement returns audit success.

## Rust input and the deferred serialized boundary · `sec:manifest3:input`

M1b does not ride with either M3 half. The library consumes ValidatedManifest from Rust authority, admits the fixed registry and executes its producers. It accepts no graph bytes, JSON values, formula strings, caller-supplied engine expressions or callbacks. M1b still lands with M6's generation/check consumer, which loads actual projection bytes and compares the complete graph with Rust authority. Its strict duplicate-key, lexical-number, shape and assertion checks must not land as an unused codec (`sec:manifest:serialization`, `dec:serialization:strict`).

ADR 007 and the glossary prescribe the projection as eventual audit input; M1's settled successor register permits Rust consumption before that boundary exists. M1b/M6 must feed the same graph and registry admission, not an audit-specific JSON schema or selection path. Their writer and reader must include ClaimAudit, budgets and every edge rather than restore the kernel's earlier restrictions (`reg:glossary:terms`, `arg:process:reasons`).

Neither half introduces a release-report loader or committed serialized report. M3a returns execution receipts; M3b returns owned verdict evidence and separate measurements. Durable storage and its strict writer/reader enter with the publication consumer before any release claims ADR 007's retained-per-release obligation is fulfilled. Engine witness bytes remain engine-owned proof data, not a second manifest interchange format. Q6's persistence recommendation is independent of the M3a/M3b split.

## Authority contracts and the closed registry · `sec:manifest3:binding`

Replace the claim payload's mandatory awaits field with ClaimAudit, whose closed alternatives are Awaiting and Bound. Awaiting contains AuditBinding or CapabilityId; Bound contains ProducerId, BudgetId and AuditRoutes. A claim cannot carry both producer and blocker. This is an explicit source API change in the draft crate, migrating constructors and tests together; NodeIds, kinds, maturity and relation contracts do not change. No existing wire schema needs migration.

ProducerId has exactly LangevinCoefficientOneValue and LangevinCoefficientThreeValue, exhaustively mapped to the existing value-claim NodeIds. BudgetId has exactly CoefficientOneV1 and CoefficientThreeV1. These internal tokens are not theory referents or duplicate label mints. Manifest-owned descriptors give claim, exact direct dependencies, capability requirements, budget ID and revision without engine types or function pointers. The audit's private registry pairs each descriptor with its own function; production callers cannot replace that table.

Claim one requires its existing dependency on coefficient one and no claim premise. Claim three requires coefficient three and claim one; coefficient three still depends on coefficient one. For these fixed producers, outgoing claim DependsOn sets must equal the descriptor sets: missing and invented dependencies both fail. CompatibleWith never supplies a premise. Claim three's scheduling prerequisite remains claim one, but its mathematical certificate contains the full checked jet, including coefficient one, rather than a Rust-substituted premise value. All six edges retain their meanings and directions (`sec:manifest:relations`).

Add duplicate-preserving `budgets: Vec<BudgetSpec>` to ManifestDraft and its validated representation. BudgetSpec names its BudgetId, designated ProducerId and pin-specific profile. The seed authors two records. Descriptors and the capability table are exhaustive manifest constants; descriptions cannot replace dependencies, formulas or capabilities. A graph with no Bound claims has no budget records. Unused, duplicate, missing and wrong-producer budgets fail.

Admission compares multisets before maps. Every Bound claim has exactly its designated implementation and every implementation exactly one present Bound claim. Producer, claim and budget identities must agree. Awaiting claims remain visible but have no implementation and cannot be selected. An omitted implementation is an input error, not inferred capability deferral. Removing a claim while retaining its implementation is an orphan error even after removing its edges. Registry checking is global, including producers outside the slice (`arg:audit:reasons`).

The seed retains four identities, descriptions, Proposed maturity and six edges, with two Bound claims and a two-claim slice. Audit closure becomes true because binding exhausts the admitted claim domain, not because the paper is complete; theory closure stays false. `seed()` returns structural authority only, ProducerRun supplies checked executions, and AuditReport later supplies the audited context. The manifest never depends on the engine.

## Checked ODE route, claim structure and verdicts · `sec:manifest3:engine`

The engine pin remains `a5cb0ab0d1763e8ed620f7c765fdd8d3b26b65ad`. An engine-neutral EnginePin in the manifest names it and the budget profile references it. Audit integration compares this value with both the dependency rev and Cargo.lock source revision. A pin move requires simultaneous capability, profile and evidence-mapping review; an old trial success cannot replace that check (`dec:audit:engine-of-record`).

The analytic identification is explicit scope: the regular germ `L = coth x - 1/x` satisfies `x L′ + 2L + x L² - x = 0`, with `L(0) = 0`, by differentiation and substitution. This is the reviewable analytic step, not producer code or an engine-checked analytic theorem. The checked obligation is its finite jet under that identification; no convergence, global equality or general analytic uniqueness theorem is claimed.

Each producer constructs the exact jet `J = [0, 1/3, 0, -1/45, 0]` and identity increment `h = [0, 1, 0, 0, 0]`, both of order 5, and uses `compute_series` on the object Compose subject with left J, right h and order None. The checked fact is Compose(J, h) = J: h has zero constant term as composition requires, the default output order is the minimum input order, 5, and no truncation premises are needed. This object route requires no Defined premise, no other premises and no assumptions, matching the engine's residual milestone fixtures. In the ambient Product context it states `R = x y′ + 2y + x y² - x` using the residual grammar's x, y, y′, Mul, Add/Sub and IntegerPower, and calls `check_evaluated_residual` with `r = 1`, `m = 4`. The engine derives the equations for degrees 0–3 from that ODE and checked object, and an empty-tuple Member certifies their vanishing. The evidence bundle retains Compose, evaluated residual and Member linkage; an unrelated subject or residual fails replay against independently constructed expected judgments.

The residual equations are triangular with leading coefficients 2, 3, 4, 5 on c₀…c₃, so their vanishing fixes c₀ = 0, c₁ = 1/3, c₂ = 0, c₃ = −1/45 uniquely, and membership of the checked object establishes the coefficient claims given the coth-to-ODE identification already stated as analytic scope.

Pin the residual and Member judgments to the assumption-free ambient Product region; substituting an empty guarded region is refused even if membership there would pass vacuously. Degrees 0–3 leave the terminal coefficient c₄ free: choosing zero in J is candidate data, not a certified coefficient-four value or an added claim.

Producer Rust supplies the fixed candidate, identity increment, residual expression and composition/truncation parameters, never the recurrence or precomputed coefficient equations. It does not calculate `3 c1 = 1` or `5 c3 = -c1²` for the engine merely to solve. The trial recurrence is an independent test expectation for engine-derived equations, not production mathematical machinery. This chooses the stronger route on its merits: equation extraction is checked where ADR 007 places reusable mathematics (`arg:audit:declined`).

Retain the two value claims rather than add a vector claim and rewire the seed. Each has a distinct wrapper around a common checked-jet helper, with target slot 1 or 3. Its expected judgment fixes the full identity-composition subject, ambient region, ODE, truncation and target slot; evidence explicitly exposes the checked coefficient there. Claim three's witness contains coefficient one and the nonlinear term connecting them, so mathematical support is inside the engine-checked object. The graph premise controls order and readiness, but is not the sole evidence of that relationship. No store handle, host-substituted scalar or cache crosses claims.

The additional coefficients checked by claim one's full jet are auxiliary candidate data verified in that execution, not assumed claim-three evidence. They introduce no reverse premise edge. Claim three similarly reconstructs its own coefficient-one slot and checks the entire residual, rather than importing claim one's accepted scalar as an unchecked premise. The existing dependency edge remains useful for scheduling and visible premise reporting without turning that procedural check into mathematical proof.

Each wrapper rebuilds the full object in a fresh store. This repeats small exact work but avoids a fifth node, identity migration or one implementation improperly bound to two claims. Certification reports the analytic scope, `n = 5`, `r = 1`, `m = 4`, target slot and degrees 0–3: finite ODE compatibility of the identified jet, not equality of a truncated polynomial and the full function. Projection of this fixed checked object does not authorize arbitrary source coefficients through the public API.

Replace the standalone solving_trial, Trial and Submission public API with M3a's registry entry. Keep its seven-coefficient oracle, joint replay and tampered-scale controls in test support; other coefficient orders do not become producers. Production uses Compose/residual/Member checking with borrowed reviewed budgets. Linear helpers may remain test-only support but cannot be a fallback if series checking refuses.

M3a admits accepted receipts and typed RunError only. M3b admits Verdict as Certified, Refuted, Undecided with Exhaustion, or Deferred with DeferredReason. Certified requires matching replayable evidence for the fixed scoped jet projection. Refuted requires contrary mathematical evidence for that same statement; a failed candidate residual or rejected supplied certificate alone is not refutation of the value claim.

For the exact projection statement, a refutation receipt pairs an accepted jet/residual bundle with a checked nonzero difference between its target coefficient and the claimed rational. The coefficient-identity route proves the difference times an exact inverse equals one. Identity-composition subject, ambient region and analytic scope stay fixed; a different unqualified ODE solution cannot refute the claim by being called the same object. A private altered-claimed-rational test exercises this receipt and Refuted mapping; production wrappers fix the seed values. This is a counterstatement about the checked object, not a claim of global analytic refutation or a public formula-injection API.

An Invalid fault, including the trial's InvalidCode::Rule tamper refusal, means SemanticInvalidity, never Refuted. Only an engine typed limit fault yields Undecided, retaining stage and resource; M3a preserves it as RunError and M3b interprets it. Unexpected setup, export or replay faults remain errors and prevent a successful report. Fault variants are matched exhaustively at the pin; neither strings nor elapsed time determine outcomes.

M3b DeferredReason admits AuditBinding, Capability, OutsideSlice and Premise with the named claim and evidence. Refuted and undecided premises do not refute or exhaust their dependent; they block it with the precise premise reason. Every M3b report contains one row for every present claim, including unselected and Awaiting claims, and no quantity verdict row. These operational blockers are not invented upstream capabilities (`arg:graph:status-coverage-consequences`).

## Premises, capabilities, routes and budgets · `sec:manifest3:execution`

Execution follows full DependsOn order, filters to selected claims and breaks independent ties by semantic name. Every selected claim's transitive claim prerequisites must be selected explicitly. Nonclaim dependencies must resolve and validate but need no verdict. M3a unlocks claim three after claim one's accepted receipt; failure stops the run. M3b unlocks it after Certified, otherwise recording the exact premise deferral. In both halves the target's own full jet supplies the mathematical relationship internally.

A claim reaches the M3b audit when dispatched through capability and premise checks, possibly returning Deferred before engine work. Reached and engine-executed sets are distinct. Unselected Bound claims are OutsideSlice; Awaiting claims keep their blockers and cannot be selected. Claim-one-only selection passes; claim-three-only selection fails premise closure. An empty slice is valid for an explicit partial run and in M3b yields visible deferrals for all claims. Registry checks always cover the whole binding domain.

CapabilityId admits ExactRationalLinearEquivalence, FormalTruncatedPowerSeries, SymbolicTrigonometry and TrigonometricIntegration. Separate engine availability from adapter implementation. The sole operational meaning of `supported` is `adapter_implemented(capability, pin)`, read from the exhaustive table below, never mere engine registration. Engine availability is documentary provenance with Present, AbsentWithEvidence or NotEstablished; absence is never inferred from an unimplemented adapter or ADR 007's initial requests.

|CapabilityId|Engine availability at the full pin and evidence|Adapter implementation admitted by M3a|Operational supported predicate and consumer|
|---|---|---|---|
|FormalTruncatedPowerSeries|Present: the engine's residual fixtures use checked object Compose subjects; `series.source`, `series.reciprocal` and `series.residual` are registered, but registration does not establish Source definedness on Product domains.|Yes: object Compose subject with the identity increment, plus evaluated ODE residual and empty-tuple Member for the fixed truncation and ambient-region contract. Reciprocal is present upstream but unused and unexposed here.|True for this exact adapter contract; both producers require it and real-pin replay checks it.|
|ExactRationalLinearEquivalence|Present: the trial's accepted linear-equivalence and coefficient-identity witnesses.|No production linear-equivalence claim route; the trial is test support. Exact rational operations and coefficient identities used by the series adapter do not constitute a generic linear-equivalence producer.|False; awaiting this adapter does not assert that the engine lacks linear solving.|
|SymbolicTrigonometry|NotEstablished by this evidence; an initial ADR request is not a verified absence at this pin.|No.|False; named adapter deferral is permitted without asserting upstream absence.|
|TrigonometricIntegration|NotEstablished by this evidence; the initial ADR does not establish present-pin availability.|No.|False; the same adapter-deferral rule applies.|

Checked Defined for total polynomial expressions on Product domains is AbsentWithEvidence at this pin: Source requires Defined(f), but both definedness routes reach the Product refusal at `region.rs:775`, while the residual frame requires Product; this is an engine capability gap, with no definedness workaround admitted here.

FormalTruncatedPowerSeries names this register's specific composition/residual adapter contract, not arbitrary series operations. Another route requires reviewed descriptor and test changes; registration alone cannot widen support. Engine availability and adapter implementation are columns of one versioned manifest table checked against the audit implementation roster, not competing caller-maintained booleans. No network lookup determines a verdict and no issue number is invented (`arg:audit:consequences`).

Both seed producers require FormalTruncatedPowerSeries. Awaiting(Capability) is refused only if adapter_implemented is true: Awaiting(FormalTruncatedPowerSeries) fails, while Awaiting(ExactRationalLinearEquivalence) may pass outside the slice despite engine availability. A Bound requirement without adapter implementation performs no engine work: M3a returns CapabilityUnavailable; M3b emits Deferred(Capability). Private descriptors using existing IDs exercise this branch without dummy theory nodes. Extensions land adapter code, the table change and real engine tests together.

AuditRoutes admits exactly Unconditional: one context, zero exclusive-route entries. No free-form assumption list, route string or constructible Exclusive form enters. M029 stays deferred until a real alternative-route claim and isolation consumer exist; its future negative conjoins incompatible routes. M020 enforces admitted binding without pretending empty route content proves isolation (`dec:graph:validation-rules`).

Both budget records select PinnedTrialLimitsV1 at the full pin: the engine's Limits::default at that immutable revision, except each field the complete route's measured completion figure requires above default, whose reviewed value is that figure rounded up to the next multiple of 500,000 and stepped further in 500,000s until headroom is at least 25 percent. At the pin the complete route — production through Member certification, exports and combined replay, for both targets — measures Work 6,073,177 and ReplayWork 3,465,362, so the profile fixes Work 8,000,000 (31.7 percent headroom) and ReplayWork 4,500,000 (29.9 percent headroom), with every other field at its default. This is a reviewed profile, not a helper's unrecorded default. Separate records allow a later reviewed change for one claim only. Receipts retain the resolved vector; pin/profile changes require review, never fallback. The profile's name records its origin, not an obligation to retain the trial's linear route.

Each executed claim receives a fresh Cas and one shared mutable Budget for exact construction, object composition, residual evaluation, Member checking, export and replay. Helpers borrow it and never renew it. Each claim pays for its full five-coefficient object, including coefficient one inside claim three's subject. M3b counterstatement checking also draws from that claim's budget. Exhaustion is a typed stop in M3a and Undecided in M3b, not permission to reset or raise limits. No numerical enclosure, tolerance or precision schedule enters.

The independently reviewed PinnedTrialLimitsV1 fixture must enumerate every field of the resolved Limits vector, including nested fields and nonnumeric policy fields if present. Check the full field-name inventory and every value against the pin's definition; an omitted, added or renamed field fails even if remaining values match. A subset, debug string or regenerated expected value is insufficient. This prevents future default changes passing by omission. Review inspects the complete resolved fixture at implementation; this note does not guess uninspected field names or values. Q3's named-profile recommendation stands with this exhaustive consumer.

## Protected evidence derivation and M012 · `sec:manifest3:status`

Maturity stays authored; Identification stays Identified and Calibration NotApplicable. Base `ftoo_manifest::Status` and its Evidence retain only Deferred and NotAClaim, with private fields. `ValidatedManifest::status` cannot yield Certified after registration or an unrelated audit. Its blocker accessor returns authored Awaiting or AuditRunRequired for Bound claims. M3a changes neither this derivation nor its assurance.

M3b introduces `ftoo_audit::AuditedStatus`, distinct from base Status, whose private constructor is reachable only inside checked report construction. AuditReport::status returns it after receipt, provenance and outcome checks. It reuses base Status for the first three axes and derives evidence from the checked verdict, retaining NotAClaim for quantities. No public node-plus-verdict function, setter, Default, deserializer or From implementation supplies another constructor. A caller may read or clone genuine audited status from a genuine report; it cannot manufacture one from unaudited data.

Manifest public VerdictClass and outcome drafts are untrusted classifications for pure checking. Naming a Certified classification in a fixture supplies neither certified evidence nor AuditedStatus. Manifest pure functions return structural diagnostics or an assessment draft, never promoted Status or AuditReport. The actual assessment and audited-status constructors stay private to the audit crate's engine-backed path. Thus the manifest needs neither an engine dependency nor a cross-crate privileged constructor; a constructible enum label is not a trusted proof token.

M011's final statement covers base derivation from identity/payload and audited evidence from checked outcomes, with only maturity authored. Proposed can be certified without becoming Retained; editing maturity cannot improve evidence. Preserve the compile-fail example naming `ftoo_manifest::Evidence::Certified`. Add separate compile-fail documentation examples that attempt to construct AuditedStatus with a Certified field, call its private derivation on a fabricated Certified draft, convert base Status or an assessment draft into AuditedStatus, construct AuditReport from caller-authored outcomes, and mutate evidence read from a report. A positive external-crate example reads audited evidence after the public audit succeeds. These test actual public construction paths, not only report field privacy (`dec:graph:status-and-coverage`).

M012 stays DeferredM1b. Future projection assertions compare with base unaudited derivation; Certified input is rejected rather than needing its own future audit to validate. Audited assertions belong to the report bound to the exact projection, budgets and pin. Its future loader must check that binding and replay evidence before comparing assertions; a Certified field never becomes its own evidence input. M1b specifies strict ClaimAudit and budget variant fields with writer, reader and first consumer (`arg:serialization:consequences`).

## Coverage and release predicates · `sec:manifest3:coverage`

Keep Coverage's slice, closure flags and gate, assigning checks to named consumers. M3a M014 GraphAdmission refuses selected Awaiting claims; M014 RegistryAdmission refuses selected Bound claims whose claim prerequisites are unselected. M3b adds M014 ReportConsumption comparing reached IDs and declared slice. Each has a distinct negative and diagnostic stage. Structural validation never claims reached-set equality before execution.

M3a M015 admits only false theory closures and ExplicitPartial; audit closure may be false or justified by complete binding. In both halves, audit closure true with any Awaiting claim fails M015 GraphAdmission even outside the slice. Registry admission then checks implementation exhaustiveness. The isolated graph negative uses an otherwise valid Awaiting claim, empty slice and no stray implementation so M020 is not its cause. M3a supplies execution evidence only, not a release assessment.

M3b treats theory closures as reviewed editorial assertions: no finite graph algorithm proves nothing was omitted. It permits true assertions but never infers them from the four-node seed. Audit closure means binding exhaustiveness, not proof success or complete selection; false flags never excuse invalid bindings. The production seed retains false theory closures, true audit closure and ExplicitPartial.

Let C be present claims, S declared slice and R reached claims. A well-formed M3b report has S = R, exactly one outcome per C, no other rows, valid provenance and prescribed blockers. ExplicitPartial passes iff the report is well formed, the declaration ExplicitPartial and no selected claim Refuted. Undecided and Deferred remain visibly uncertified; malformed proof construction aborts reporting and cannot exploit partialness.

Complete passes iff the report is well formed, the declaration Complete, all closure flags true, C nonempty, S = R = C and every claim Certified. Binding, dependency, budget and evidence checks remain prerequisites. Empty C, an unselected/Awaiting claim, deferral, exhaustion or refutation independently prevents completeness. Proposed maturity and NotApplicable calibration do not block this coverage predicate; editorial policy is a separate consumer (`arg:graph:status-coverage-reasons`).

M3b reports every out-of-slice claim and blocker, with quantities exposed through status rather than verdict rows. Iteration uses semantic identity, independent of execution order. The library distinguishes InputError, SemanticInvalidity, MathematicalFailure and Incomplete. Reserve executable codes 0 for pass, 2 for input error, 3 for semantic invalidity, 4 for mathematical failure and 5 for incomplete coverage. Incomplete and code 5 are an explicit extension beyond ADR 007's three failure categories: failed complete coverage need not be mathematical refutation. No CLI enters either half.
