# Manifest addressing and permanent lifecycle history · `proposal:manifest:addressing-lifecycle-bite`

## Boundary and evidence · `sec:manifest4:boundary`

M4 admits the authority's tag registry, permanent binding and identity history, retirement admission, and live, retired and out-of-slice addressing stores together with their validator and resolution consumer. It does not change mathematical objects, graph edges, audit input, status derivation, coverage assessment or budgets. A live handle establishes addressability in the declared slice, never certification (`reg:manifest:successors`, `dec:tags:bound-to-labels`, `dec:graph:status-and-coverage`).

The reference is main at `271666266c216ba62b71db20cf2241e6d221ae72`. The complete `crates/ftoo_manifest` supplies four permanent NodeIds, two kinds, six edges, two Bound claims, the two-claim coverage slice and 29 registered rules: 17 enforced, two structural and ten deferred. The audit's registry, runner and report consume that graph through NodeId, preserve base Deferred evidence, privately construct AuditedStatus, and assess release against engine pin `a5cb0ab0d1763e8ed620f7c765fdd8d3b26b65ad`. These are the implementation constraints against which the settled M1 and M3 notes are read (`proposal:manifest:kernel-bite`, `proposal:manifest:audited-binding-bite`).

ADR 003 requires one authority-owned registry covering labeled theory objects, not a registry of every Markdown section label. Its examples include quantities, claims, rulings and evidence links; only quantities and claims are admitted NodeKinds. M4 covers all four admitted theory identities and does not manufacture ruling or evidence-link nodes. Each later theory-kind admission must join this same registry. Document labels, producer IDs and budget IDs do not become theory objects by having names (`dec:tags:bound-to-labels`, `dec:graph:closed-authority`, `reg:glossary:terms`).

The scope is a single reviewed M4 bite. Registry data, lifecycle validation, materialized stores, public resolution and exact-fault fixtures enter together. There is no M4a/M4b split: separating binding from retirement would admit tags before their required lifecycle machinery, and separating the stores from resolution would defer the consumer which distinguishes the states. The bounded implementation is a manifest-only library addition with four real bindings, a small event vocabulary and no external runtime, codec or engine work (`dec:process:signed-bites`, `arg:process:consequences`).

## Registry and spelling · `sec:manifest4:registry`

A tag in admitted Rust data is a member of the closed `TagId` enumeration. Its descriptor contains its exact human spelling and one NodeId; the latter's existing `semantic_name()` is the bound label. Descriptors live in one exhaustive manifest-owned match/table, and `TagId::ALL` enumerates them. A submitted handle is an untrusted `&str`, not a new TagId or semantic identifier. Only exact equality with a registered spelling recognizes it. Rust enum names, label substrings, display descriptions and prefixes never infer the target (`dec:graph:closed-authority`, `arg:tags:reasons`).

No public constructor accepts a spelling/target pair, no map insertion or binding setter is exported, and no lifecycle operation carries a replacement target. Stores contain TagIds and obtain targets from the permanent descriptor; they never copy an independently editable target into each store. Moving a handle between stores therefore cannot rebind it. The identity catalog remains the existing closed NodeId enumeration even after an identity ceases to be present in a particular graph. TagId is an addressing token, not another label mint or a second theory identity.

Spelling admission requires a nonempty Rust string containing no Unicode whitespace and no Unicode control character, using Rust's `is_whitespace` and `is_control` predicates. There is no prefix grammar, colon requirement, kind-specific alphabet, numeric suffix grammar or length limit. “Short” remains an editorial choice about recognizability; an arbitrary machine length limit has no support in ADR 003. These lexical restrictions make a handle usable as one visible token and prevent hidden line breaks; they do not decode its meaning. Exact UTF-8 bytes determine equality and ordering, with no trimming, case folding or Unicode normalization. Two canonically equivalent Unicode spellings remain distinct handles if separately admitted; review should avoid confusing spellings, but the resolver must not merge them. Rendering escapes belong to M5/M6, not tag identity (`arg:tags:reasons`, `arg:tags:consequences`).

All unsuccessful public lookups, including an empty string or a string containing whitespace, are UnknownTag preserving the original input. InvalidTagSpelling is an authority-admission fault, not a fourth lifecycle state or a public parser outcome. This avoids treating a typo as an invented object or silently repairing an old handle. Tests use punctuation-bearing and non-ASCII private spellings to prove exact opaque lookup, without admitting them as production tags.

The following are proposed permanent admissions, not claims about existing prose usage or notation commands. Their ergonomic prefixes distinguish the two quantities from their value claims for a reader only. Even `v:1` does not tell a consumer that it names a claim; only the bound NodeId does.

|TagId variant|Exact spelling|Existing NodeId|Bound semantic name|
|---|---|---|---|
|LangevinCoefficientOne|`c:1`|LangevinCoefficientOne|`def:langevin:coefficient-one`|
|LangevinCoefficientThree|`c:3`|LangevinCoefficientThree|`def:langevin:coefficient-three`|
|LangevinCoefficientOneValue|`v:1`|LangevinCoefficientOneValue|`claim:langevin:coefficient-one-value`|
|LangevinCoefficientThreeValue|`v:3`|LangevinCoefficientThreeValue|`claim:langevin:coefficient-three-value`|

Each tag binds exactly one identity; ADR 003 does not require the reverse mapping to be one-to-one. Multiple permanent handles for one identity are permitted only by a reviewed additional TagId admission, with its own history entry and spelling rationale. M4 admits exactly one per identity and no alias preference or canonical-display selector. Changing a spelling means admitting a new handle and retiring the old handle with a reason about the handle itself; it never edits an existing descriptor. Changing the theory object means a new NodeId and new handle, not a spelling trick (`arg:tags:consequences`, `arg:graph:closed-authority-consequences`).

## History and retirement admission · `sec:manifest4:history`

The authority retains an append-only Rust history ledger beside the descriptor table. Its record is `HistoryEvent` with a positive `u32` ordinal, an `authority_record` string naming a reviewed record in label form, a nonblank reason string and a closed `HistoryChange`. The change alternatives are AdmitIdentity with NodeId and its nonblank original formulation, AdmitTag with TagId, RetireTag with TagId, and RetireIdentity with NodeId. There are no Rebind, Rename, Delete, Reactivate or arbitrary metadata alternatives. NodeId and TagId appear as typed values; event strings cannot mint either. The authority-record string is provenance, never an executable rule or an addressing target.

Ordinals must be unique and contiguous from one and are replayed in ordinal order, independently of array order. Every NodeId in `NodeId::ALL` has exactly one AdmitIdentity, every TagId in `TagId::ALL` exactly one AdmitTag, and an AdmitTag follows admission of its descriptor's target. Identity admission records the original formulation as historical prose, not an executable definition; it is not required to equal a later editorial description. The semantic name and expected kind remain in the permanent NodeId mapping, and are exposed with the history through that mapping. This avoids a second editable identity-name table while retaining what referent was admitted and why. Every identity has at least one admitted tag in the completed ledger, including identities absent from the supplied graph and retired identities.

The seed ledger has eight records: the four identity admissions in the order coefficient one, coefficient three, value one, value three, followed by the four tag admissions in the table order. Identity events explicitly describe a retrospective registration of the M1 seed, cite `proposal:manifest:kernel-bite`, and retain its four original descriptions verbatim. They do not invent dates or claim that M1 already maintained this ledger. Tag events cite `proposal:manifest:addressing-lifecycle-bite` and state that the handle addresses the corresponding existing seed referent. These record names are references to design records, not new mints at each event. Cross-surface validation of Rust-held citations remains with M6; M4 checks a three-component lowercase ASCII letter/digit/hyphen label shape but cannot claim citation resolution from that shape (`conv:adr:labels`).

RetireTag requires a previously admitted, nonretired tag whose target has not already retired; it permanently withdraws that handle without retiring the object. RetireIdentity requires a previously admitted, nonretired identity and permanently withdraws the object; every associated handle becomes retired. A duplicate retirement, admission after retirement, tag admission to a retired identity, or tag retirement after identity retirement is refused. A prior tag retirement remains its own reason when the identity later retires. An identity retirement is permitted even if all its handles have already retired; the object act still has independent meaning and history. No replacement link or redirect is admitted in M4: the reason may explain a correction, but consumers cannot follow prose to another target.

Each retirement retains its ordinal, original target, authority-record citation and nonblank reason forever. For a handle explicitly retired before its target, the retired-store cause is TagRetirement referencing that event; otherwise retirement of the target yields IdentityRetirement referencing that event. Both cause alternatives are closed and inspected exhaustively. The original admission and every subsequent event remain available through immutable history accessors. Git review supplies chronological authority and signatures; wall-clock timestamps, commit hashes and runtime persistence files are unnecessary fields in the registry.

An AddressBook refuses a graph containing a retired identity, with RetiredIdentityPresent. A retired tag whose identity remains active is valid, but cannot resolve through that tag. A historical identity absent from the graph remains known; absence alone is not retirement. This distinction allows tombstones to survive future graph removal without requiring a fake current NodePayload or a new status value. Existing graph validation still independently refuses dangling edges and coverage references; retirement cannot excuse them. An actual future retirement must review graph edges, producer bindings and budgets wherever that removal requires changes. M4 supplies the machinery and its fixture consumer before that authority act, without retiring a production node or revising M020 (`reg:manifest:successors`, `arg:graph:closed-authority-consequences`).

Never-rebind is structural for values and operations admitted by this API: a caller cannot supply a second target and an event cannot express one. No Rust table or validator can prevent a maintainer from rewriting both the source of an exhaustive mapping and its tests. Across reviewed versions, preserving existing descriptors, NodeId semantic names/kinds and prior history records is an explicit append-only review obligation, supported by independent literal fixtures. The design does not falsely mark source-history immutability as a runtime theorem. An attempt to correct an old formulation into a different object requires retirement and a new identity under ADR 001; judging “different object” remains semantic review, not string comparison.

## Slice semantics and three stores · `sec:manifest4:stores`

`AddressBook<'a>` borrows one immutable ValidatedManifest and owns three disjoint private stores: live entries, retired entries with retirement cause, and out-of-slice entries with exclusion cause. It is constructed only by `addressing(&ValidatedManifest)`, which validates the compiled registry/history and derives the partition. It exposes immutable store iterators, immutable history inspection and `resolve(&str) -> Result<NodeId, TagResolutionFault>`. It exposes no graph mutation, arbitrary authority injection, detached reusable resolution cache, status constructor or release predicate. The borrow binds the store partition to the exact graph and coverage declaration used to derive it; another graph requires another AddressBook.

Let S be `graph.coverage().slice`. For the two admitted kinds, a present claim is addressable precisely when it belongs to S; a present quantity is addressable precisely when reachable from S by zero or more directed DependsOn edges from dependent to prerequisite. This is the support of the audited slice, not a replacement slice declaration. Traverse only DependsOn, never CompatibleWith, reverse edges or prose mentions. Claims encountered during traversal but absent from S do not become live: M3's selected-premise check remains its own admission obligation. M4 accepts a structurally validated graph without pretending to run the audit registry. Thus a graph awaiting M3 registry admission can have an AddressBook but cannot claim an admissible audit or release (`sec:manifest3:coverage`, `sec:manifest3:execution`).

This support rule is a recommended interpretation of ADR 003 where the records leave a choice: literal membership would make every quantity out of slice because M013 admits claims only; treating all present quantities as live would give the empty audited slice a positive addressing surface unrelated to coverage. The dependency support includes exactly the quantities needed to state selected claims without adding quantities to Coverage or changing the complete-release predicate. It supplies no evidence value. A selected claim deferred by capability, premise or resource exhaustion still has a live handle; an unselected claim awaiting a capability is out of slice for addressing even though M3 deliberately preserves its capability blocker in the report. Those are different questions, not contradictory states (`dec:graph:status-and-coverage`, `arg:tags:reasons`).

Derivation examines every admitted tag, including historical tags whose targets are absent. Retirement takes precedence over absence and slice membership. Otherwise an absent target gives OutOfSlice(TargetAbsent); a present unselected claim gives OutOfSlice(ClaimNotSelected); a present quantity outside the dependency support gives OutOfSlice(QuantityOutsideSupport); every remaining tag is live. These are three causes of one out-of-slice state, not additional lifecycle states. There is no authored slice flag, no independently authored store assignment and no fallback from a retired handle into a live alias.

In the production seed all four handles are live and the retired and out-of-slice stores are empty but typed. With only value one selected, `v:1` and `c:1` are live, while `v:3` and `c:3` are out of slice. The compatibility edge from coefficient one to coefficient three cannot bring `c:3` into support. With an empty slice all four are out of slice. These states can change when a different immutable graph is supplied; live ↔ out-of-slice is a projection of coverage, not a retirement event. Both nonretired states may become retired by a reviewed event; retired is terminal. Store changes caused by coverage are already accounted for by the graph's coverage history and do not inflate the permanent ledger with every consumer invocation.

Every tag belongs to exactly one store and the union equals the complete TagId table. All iterators sort by exact tag-spelling bytes; history sorts by ordinal. Construction derives and checks the partition before exposing any lookup. Invalid history suppresses classification for affected entries and prevents returning an AddressBook; it never silently drops a tag. The production construction path has no unchecked empty-store shortcut.

## First consumer and refusal vocabulary · `sec:manifest4:consumer`

The first consumer is registry/history admission plus the public resolver exercised over the real four-object seed and exhaustive private lifecycle fixtures. This is the honest M4 minimum: there is a genuine human-handle-to-NodeId boundary to check, and the settled successor register explicitly requires its machinery before retirement or tag admission. A thin adapter forwarding the same Result would add no independent check. M1b remains different: an unused codec cannot establish the projection's every-edge or stale-byte guarantees, while M4's resolver directly exercises the new addressing guarantee (`arg:process:reasons`, `sec:manifest:serialization`, `reg:manifest:successors`).

The resolver accepts only exact registered spellings and returns a NodeId only from the live store. It does not return Option, a display placeholder, an alternative tag, a recovered label or a successful partial result. `TagResolutionFault` is a closed public enum deriving equality and implementing Error/Display; every fault owns the exact input string so refusal evidence survives the caller's buffer. Known-tag faults also carry the TagId and bound NodeId. Resolution has these exact alternatives and message forms, with strings debug-quoted so whitespace and control inputs remain visible.

|Fault|Required payload|Display contract|
|---|---|---|
|UnknownTag|original input string|`tag {input:?}: unknown`|
|RetiredTag|input, TagId, NodeId, TagRetirement or IdentityRetirement with ordinal, reason and authority record|`tag {input:?}: retired; label {label}; event {ordinal}; authority {authority_record}; reason {reason:?}`|
|OutOfSliceTag|input, TagId, NodeId, TargetAbsent / ClaimNotSelected / QuantityOutsideSupport|`tag {input:?}: out of slice; label {label}; cause {cause}`|

The cause tokens in Display are respectively `target-absent`, `claim-not-selected` and `quantity-outside-support`. “Unknown” is the absence of a registered handle, not a fourth store. None of these is an audit Verdict, DeferredReason or Disposition. Future tag-facing positions must propagate these refusals as build errors with their own site location; the library does not claim a build gate exists before those positions land. Reading history to explain a retired tag is permitted but is not successful address resolution (`dec:tags:bound-to-labels`, `arg:tags:declined`).

The retired store lands empty in production because no repository retirement is justified by these records. Private fixtures retire an existing seed handle, and separately retire a seed identity in a graph from which that identity and its referencing edges have been removed. They retain the permanent catalog, original mapping and history. Those fixtures prove actual retirement checks and lookup refusals; they do not publish a fake retired theory object. Out-of-slice behavior is exercised using the real graph's one-claim and empty coverage declarations. Lifecycle machinery is therefore checked before its first production retirement, rather than marked enforced merely because its production domain is empty.

## Crate boundary and modules · `reg:manifest4:modules`

The registry is Rust authority in `ftoo_manifest`, which remains standard-library-only. It is a separate authority-owned addressing component over the same NodeIds, not a caller-owned second graph. `ManifestDraft`, `ValidatedManifest`, `Snapshot`, `OutcomeDraft`, Status and Coverage receive no fields. The audit crate receives no tag duty or dependency. Keeping tags outside Snapshot follows ADR 003's nonsemantic-handle decision: changing address availability cannot recertify a claim or invalidate an otherwise matching M3 semantic snapshot. A future rendered artifact must bind its addressing projection as well as its semantic graph; an M3 report alone never attests a rendered handle (`arg:tags:reasons`, `sec:manifest3:status`).

|Path under `crates/ftoo_manifest/`|M4 responsibility|
|---|---|
|`src/tags.rs`|Private module containing TagId, exhaustive descriptors, spelling checks, public addressing entry point, private AddressBook fields, typed stores, resolution and immutable inspection APIs. Re-export the public types through lib.rs.|
|`src/tag_history.rs`|Private module containing the eight seed history events, closed event/cause types, ordinal replay, retirement and coverage-of-catalog validation; immutable public event views have no constructors.|
|`src/tag_validation.rs`|Private module implementing admission diagnostics, prerequisite suppression, dependency support and store-partition checks; private draft representations retain duplicates for mutation fixtures.|
|`src/tag_tests.rs`|New `#[cfg(test)]` module with seed resolution, private mutation fixtures, transition matrix, exact faults and independent history/descriptor expectations.|
|`src/lib.rs`|Declare modules, document the addressing assurance boundary and explicitly re-export TagId, AddressBook, immutable entry/history views, addressing, TagResolutionFault and addressing diagnostic/error types.|
|`src/validation.rs`|Append M030–M036 to RuleId and RULES only; preserve existing rules, stages, diagnostics and validation algorithm.|
|`src/tests.rs`|Update register allocation/state/count expectations and retain all existing graph/audit-consistency tests unchanged in meaning.|

No changes enter `src/identity.rs`, `src/graph.rs`, `src/coverage.rs`, `src/status.rs`, `src/audit.rs`, `src/budgets.rs`, `src/seed.rs`, any `ftoo_audit` file, manifests, lockfiles, generated artifacts or documentation outside the implementation's own API documentation. NodeId semantic names and kind mappings are read, not reminted. Tag spelling and binding descriptors are kept together in tags.rs; event records never duplicate that binding table. Private test drafts are compiled only for tests or used behind private validation helpers, never exported as an authority-injection API.

`AddressingDiagnostic` contains RuleId, `AddressingStage` (CatalogAdmission, HistoryAdmission or StoreConstruction), a closed `AddressingFault`, optional TagId and NodeId, and `AddressingLocation` (Descriptor index, History index, Identity or Store). `AddressingErrors` owns the sorted nonempty diagnostics and exposes an immutable slice. This separate diagnostic family avoids adding tag fields or stages to every audit Diagnostic constructor. Runtime resolution has the distinct TagResolutionFault family above, not an invented GraphAdmission error.

Admission first checks descriptor spellings and duplicates; then ledger record metadata and ordinal structure; then replays admission/retirement and verifies catalog completeness; then checks retired-identity absence and computes support/stores. Malformed ordinals prevent replay globally. Invalid event metadata prevents replay of that event and dependent checks for its entity; catalog and other independent errors still accumulate. Store construction requires successful catalog and history admission. Diagnostics sort by rule, exact spelling where present, semantic name where present, original location and fault discriminant, with absent sort keys preceding present ones. Duplicate spellings report every conflicting original descriptor position. History indices always refer to input positions; sorting never changes their meaning.

## Registered validation rules · `reg:manifest4:rules`

M001–M029 retain their exact landed statements, scopes, states and deferred reasons. In particular M005 is not broadened silently: the new addressing structural guarantee has M030. M011/M012, M013–M015 and M020–M029 remain untouched. M001–M004/M012 remain DeferredM1b, M016–M019 DeferredM2 and M029 DeferredExclusiveRoutes. M4 adds one structural rule and six enforced rules, yielding 36 rules: 23 enforced, three structural and ten deferred. Existing deferral reasons remain byte-for-byte fixtures (`dec:graph:validation-rules`).

The quoted statement column below is the literal RuleSpec statement. Scope and named fault are independently tested. New enforced rules carry no deferred reason; M030 is Structural. Closed AddressingFault variants named in the table carry the offending IDs/positions and expected/actual ordinal or store where applicable; the diagnostic supplies stage and location. M035 and M036 enforce the real derived-store/resolution consumer rather than a promise about future renderers.

|Number and state|Statement|Scope and exact firing negative|
|---|---|---|
|M030 — structural|“Tag targets and spellings are fixed; no lifecycle operation can rebind or rename a tag or reactivate a retired tag.”|Every public addressing value and operation. External-crate compile-fail tests attempt descriptor/AddressBook field construction or mutation and a nonexistent rebind/reactivate method; exhaustive positive descriptor checks cover all four targets. No runtime mutation is claimed as its negative.|

M034 uses AlreadyRetired for RetireTag after target retirement as well as repeated direct retirement, carrying the effective retirement event. An additional identity admission after retirement fires M032 DuplicateIdentityAdmission; an additional tag admission after its own retirement fires M032 DuplicateTagAdmission. Their failed uniqueness prerequisite suppresses terminal-state checking for that event, so a negative cannot pass through an accidental extra rule. Retiring a not-yet-admitted entity in a ledger which admits it later isolates M034 without making M032 completeness fail. A missing identity-admission fixture omits that identity's dependent tag events too and pins both MissingIdentityAdmission and MissingTagAdmission under M032; a missing tag-admission fixture pins MissingTagAdmission alone. Renumber those fixtures contiguously to avoid an unintended InvalidHistoryOrder. M032 failure suppresses M036's completed-history coverage check for affected entities; unbound history is never misreported as a runtime UnknownTag.

M035's checker compares an explicit proposed partition with the ledger-derived effective retirement and the graph-derived support, independently of the code that fills the stores. It checks multiplicity before maps. M036's catalog-completeness half emits a RuleId-bearing HistoryAdmission diagnostic; its live-only resolution half is enforced by consumer tests of TagResolutionFault, which carries no RuleId. Register tests therefore expect a diagnostic only for the catalog half. M036 cannot be credited by `is_err`: its resolution test oracle compares the exact public fault, target, cause, event, reason, original input and Display output. Register membership tests pin all 36 entries, their statements, scopes, states, counts and reasons with independently written expectations. No source-history comparison, citation-resolution claim or renderer rule is smuggled into an Enforced entry.

## Deferred serialization and named successors · `sec:manifest4:serialization`

M4 lands no bytes, Serde dependency, wire.rs, schema version or projection change. M1b/M6's eventual single projection must add the complete tag descriptor table, permanent identity admission history and retirement events, plus separate live, retired and out-of-slice runtime stores. Targets are stable NodeId semantic names; tag spellings remain opaque strings; history ordinals are exact integers; store and cause tokens are explicit kebab-case variants. Retired and absent identities must survive projection even when absent from active `nodes`. These are obligations on that future contract, not an already shipped top-level JSON shape (`sec:manifest:serialization`, `dec:serialization:strict`).

The future loader must preserve multiplicity, reject unknown fields and duplicate keys before structural admission, resolve closed TagIds and NodeIds through their explicit spellings, compare the projected bindings/history against Rust authority, and verify any serialized store assertion against the same derived partition. It must not trust a serialized live flag or rewrite a retirement reason. Generation/check must compare the entire addressing export and all graph edges, then check canonical bytes. M1b's original kernel sketch cannot be used to omit M3 or M4 data. The audit consumes the same validated semantic graph from that projection; it does not acquire a tag parser or a second input format.

M5 owns renderer use of resolved NodeIds, notation commands, host-language escaping and collision/separation tests. M6 owns tag-facing unit admission, rendered-Markdown tag display with hidden bound labels, generated runtime separate-store messages, per-site build refusal, the weld and cross-surface Rust/Markdown mint and citation checking. Future consumers must use the fallible live resolver at every tag-facing position and test unknown, retired and out-of-slice handles at each position. The accepted coverage-authorability coupling is that prose can address through tags only the audited slice and its dependency support, so M6's tag-facing positions inherit refusal of all four seed handles when the slice is empty. M4's library tests cannot establish those absent surfaces. Durable audited-report serialization is supplied by the retention consumer; history records still neither replay witnesses nor promote evidence.

Actual production retirement, corrected-object admission, additional aliases, preferred display selection, ruling/evidence-link kinds and additional slice-support policies for future kinds are named deferrals. New kinds must extend the exhaustive support decision with their own consumer instead of inheriting a default “live”. None of these deferrals blocks implementing the two-kind M4 boundary. If implementation requires changing M3's audit boundary, status derivation, coverage predicate or budget profile to make M4 work, the bite is BLOCKED for that reason; it must not widen this note silently.

## Test evidence and verification · `sec:manifest4:tests`

The production positive control calls seed(), then addressing(), then resolves each of the four exact spellings and feeds the returned NodeId into the existing immutable graph lookup. Independently assert the four descriptor triples, eight history records with original descriptions and citation strings, three-store cardinalities 4/0/0, all four target names, and all six unchanged graph edges. This is a real resolver consumer, not a fake extra production facade. Reading base status after resolution must still return Deferred for claims and NotAClaim for quantities; resolving `v:1` never supplies AuditedStatus.

For each enforced admission rule use a duplicate-preserving private draft mutation and assert the exact RuleId set, AddressingFault, stage, IDs and original locations. The private checker accepts fixture descriptors/history only inside the crate; production callers cannot select them. Each isolated fault has a restoration control. Multi-defect fixtures explicitly name their whole expected rule/fault set. Reverse descriptor/event input order while retaining ordinals to prove stable semantic results and correct original locations. Test malformed ordinal suppression without accepting a later accidental retirement or store error as success.

The retirement matrix covers live tag retirement; out-of-slice tag retirement; identity retirement with every affected tag retired; tag retirement before identity retirement preserving the earlier tag cause; retirement before admission; repeated retirement; tag admission to a retired target; and refusal when the retired identity is still present. To test identity removal, remove coefficient three and all incident edges in a private seed graph, keep the slice empty and retain the historical catalog. This is a structurally valid graph for the addressing consumer, not a claim that its unchanged audit producer roster passes M020. Pin Addressing admission success for the valid tombstone case and the full RetiredTag payload thereafter; do not run or weaken audit binding to make this fixture pass.

Coverage fixtures independently assert the full seed partition, claim-one-only partition, empty-slice partition and TargetAbsent on the same historical handle without a retirement event. A compatibility-only path must not create quantity support; a transitive dependency path must. Use the existing quantity-three → quantity-one dependency with a private structurally valid selected claim-three graph to demonstrate traversal, while documenting that M3 separately refuses missing selected claim premises. A present Awaiting claim with empty selection remains OutOfSliceTag for addressing while expected_deferral retains its existing AuditBinding/Capability behavior. Retirement always wins over TargetAbsent, and live never implies Certified.

Resolution negatives assert UnknownTag for an unregistered near miss, case change, surrounding whitespace, empty input and unknown prefix; they preserve exact input including control characters in Display. A private catalog binds a misleading prefix to an existing different-kind target and must resolve to the table's NodeId, proving there is no prefix-derived kind. Unicode normalization variants are unequal; exact registered Unicode input succeeds. Each retired and out-of-slice cause is exercised with its complete independently stated message, including the original label and retirement reason where applicable. No unknown handle falls back to a label string or a different alias.

Compile-fail documentation tests cover private descriptor construction, target mutation, AddressBook construction/store mutation, nonexistent rebinding and reactivation, and the inability to use a tag or resolution result as authored evidence.
