## Findings

- Environment: Chromium 156.0.8078.100 in a desktop application's embedded Electron pane, Linux x86_64. No network resource and no console message on any of the six pages. All three declared faces load everywhere; mathematics is drawn in Pagella Math (computed family on every `math`).
- H5 is the clearest rendering gap: the library's `mathvariant` double-struck, bold and script on single letters draws plain math-italic or upright letters; only the Unicode spelling with `mathvariant="normal"` shows the alphabets.
- H1: `menclose` draws no box in this engine (the CSS border repair does); the equation numbers (H1 22.1, H3 A.21) are not beside the display; at 375 wide the H1 formulas overflow the column (document scrollWidth 513 versus 375) and the repair's box does not enclose its overflowing content.
- Underbrace stretch: painted stretched across the base in H1 and the base width in H4, yet `getBoundingClientRect` of the `mo` is 6.4 x 3 px; do not use that rect to judge stretching. In H4 the brace spans only the base, not "pending".
- Small capitals: could not be determined, and the answer is probably that there are none. The pages set `font-variant-caps: small-caps` (with computed `font-synthesis: weight style small-caps`) on the handles, but the handle text in the markup is already upper case, so no lowercase letter is substituted: the handles show as ordinary capitals at 0.8333 em (9.87 px inside the script size). The Pagella faces do carry real `smcp` and `c2sc` GSUB features (regular and bold), so lower-case text would get real small capitals; none is shown. No italic Pagella face is declared or loaded (document.fonts has no italic entry), so the italic handles (and the refrains elsewhere) are the browser's synthesized oblique of the regular face, not a true italic. Stroke-weight comparison against full capitals was not possible (no small capitals present). Regular: real small capitals are available but unexercised; italic: synthesized slant, small-caps not exercised.
- Accessibility: tree inspection only. Handles are links with their handle text as name; the math element has no role or name in the read_page output (children flattened).
- Surprising: the first reload after the pane was hidden reported innerWidth 0 (discarded); the pane's DPR at desktop is 1.667, not 1.
- Unobserved: other browser engines, real zoom, screen-reader speech, DPR 1 as a controlled run, candidate hashes.
